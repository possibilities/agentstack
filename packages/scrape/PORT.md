# Scrape engine port

Source snapshot: `agentscrape` commit `d643e7a7419d698500acbb1c8151cb09c054a539` (MIT; retained in `LICENSE`). Extraction, feed, preset, queue, corpus and HTTP policy code originate there. Stack compiles the engine with Node 24+; `src/subprocess.ts` replaces the Bun-specific process runner, and `scripts/copy-assets.mjs` ships official preset JSON, the configured canary list and the recorded corpus alongside `dist`.

The package publishes a Package API, not a CLI, independent MCP process, installer or LaunchAgent. Operator-only filesystem and browser-session operations are socket-only. The former separate data root is **not imported**: the queue, retries, failed records, captured corpus and local data-only presets live under `<STACK_STATE_DIR>/scrape`. Direct fetches return a versioned, classified envelope; local browser-backed extraction needs the optional agent-browser executable and explicit unrestricted egress consent. The private Stack browser binary is preferred when installed.

`pnpm --filter @stack/scrape test` replays every shipped preset's captured samples, checks drift classification and verifies isolated paths without external network or a visible browser. A green replay is not current provider health: `scrape_canary_inventory` reports configured coverage and `scrape_presets_check` is an explicit socket-only live operation. The source snapshot configures only the DeepWiki wiki-page canary; eight other presets have no live canary yet. An operator can provide a local canary file and an already signed-in `session`; the runner reuses but does not close it. Running authenticated provider checks needs that session and a separately granted browser lease. No live validation was inferred from fixtures.
