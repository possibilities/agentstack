# 39. Re-read Worker state into the originating Bot thread

Status: accepted, 2026-09-24. Extends [ADR 0033](0033-agent-facing-event-subscriptions.md)'s snapshot-driven delivery, [ADR 0032](0032-bot-mcp-invocation-context.md)'s Bot lineage check, and [ADR 0038](0038-durable-acp-worker-execution.md)'s durable Worker turns. No ACP progress notification is itself a Bot instruction or a completed delivery.

Extended by [ADR 0060](0060-claude-sdk-workers.md), which uses the same wakeups and exact runtime-instance fence for Claude SDK Workers.

The `workers` Package API publishes `worker_changed` with the Worker ID as scope on turn admission, permission requests and responses, cancellation, completion, failure and recovery. Token-by-token transcript progress remains on the coalesced global invalidation, not the Bot wakeup topic. The originating Bot thread subscribes through the existing owner-managed `events_subscribe` tool to `worker_changed` with `scope` equal to the Worker ID and `readOperation: worker_status` with that same ID. The owner checks that the Worker belongs to the exact Bot and originating thread before subscription, after reconnect, and before every fresh read. It then uses the existing idle-thread queue and current Bot-instance/lineage check to deliver changed snapshots as Codex turns. The initial snapshot is returned to the tool call; no historical event sequence or automatic retry of an uncertain turn is claimed. Other Worker subscriptions through the Bot event tools are refused because unbound socket reads would otherwise expose another Bot's records.

Each ACP Worker session receives signed per-Worker internal Package API MCP URLs instead of the owner's unbound base URLs. The URL proves a Worker ID and a random account-runtime instance; the owner verifies both against `worker_status` and `worker_runtime_list` on each tool listing and call. A stopped/closed Worker or replaced ACP process fences an older URL, while `session/load` binds a fresh one before its MCP discovery. Worker-bound MCP listings contain only read-only Package API operations, and mutation or Bot event-subscription attempts are refused. Role-defined external MCP servers still follow their authored definitions. The existing same-OS-user local trust boundary remains; this does not isolate an agent that can run arbitrary shell commands as that user.

AgentStart's later [OpenCode V2 cutover](https://github.com/possibilities/agentstart/blob/main/docs/adr/0044-cut-over-opencode-command-to-v2.md) shadows the public `opencode` command without removing V1. This Worker account implementation deliberately pins `~/.opencode/bin/opencode` for Grok and Codex ACP: its credential evidence and no-turn/turn probes are V1-specific. A V2 Worker migration must test its different credential storage and ACP selection against multiple isolated accounts before retiring that V1 executable; PATH selection is not proof of equivalence.

The V1-specific Worker pin and credential evidence in this paragraph were superseded by [ADR 0040](0040-opencode-v2-worker-accounts.md) after isolated V2 catalog and real Worker-turn verification.

The canvas keeps Worker account/runtime/session data and its `/x.md` twin accurate through the global change topic. Dedicated Worker controls and review views await an explicit UI request.
