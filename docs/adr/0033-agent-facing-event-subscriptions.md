# 33. Deliver Package API event snapshots into subscribed Bot threads

Status: accepted, 2026-09-24. Extends [ADR 0007](0007-bot-scoped-change-events.md)'s payload-free invalidations, [ADR 0023](0023-discovery-snapshot.md)'s operation metadata, and [ADR 0032](0032-bot-mcp-invocation-context.md)'s Bot/thread correlation. No event topic becomes a payload-bearing socket notice.

Delivery policy superseded by [ADR 0120](0120-codex-native-input-admission.md), 2026-09-29: `turn/start` already performs native start-or-steer admission. The original idle wait, per-thread completion barrier, and synthetic human-message delivery were mistaken. Use standalone tool output and return on admission; retain ownership, exposure, coalescing and feedback-loop rules.

The owner-managed MCP transport adds `events_catalog`, `events_subscribe`, `events_status`, and `events_unsubscribe` tools for Package APIs that declare events. The catalog exposes their topic lexicon and read-only operations. A Bot thread chooses a topic, scope, and one read-only operation with arguments. Subscription happens before the first read; the tool returns that initial value, and each later notice triggers a new read. The owner stores only subscription intent and delivery status in a private SQLite database, not event values. After a socket interruption or owner restart it rebinds the same Bot/thread to the current launch, resubscribes, and delivers a fresh snapshot rather than inventing replay. Identical values are suppressed, bursts coalesce, oversized values produce a bounded pointer to the read operation, and a repeated subscribe call is idempotent for the same Bot/thread/topic/read choice.

Before `turn/start`, the owner checks the exact Bot launch and that the target is loaded within its `mainThreadId` subtree, including after connection setup. It never substitutes another thread. Under ADR 0120 it submits standalone tool output immediately and records admission acknowledgement without waiting for idle or completion. It records a failed or unknown submission outcome without blind retry; a later notice may carry the latest value. An unloaded thread retries with bounded backoff, while a deleted Bot's subscriptions are pruned. A Bot cannot subscribe its own thread to chat/thread invalidations: admitted input would generate a self-sustaining change loop. Other scoped event subscriptions remain available. Subscription input is explicitly labelled observed data, not human instructions. This is a snapshot-driven workflow, not an ordered event log; consumers needing every intermediate transition need a separate durable source API.
