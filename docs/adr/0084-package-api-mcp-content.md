# 84. Present typed Package API output as native MCP content when declared

Status: accepted, 2026-09-26. Extends [ADR 0008](0008-mcp-rpc-transport.md)'s generated MCP tools, [ADR 0010](0010-shared-websocket-transport.md)'s socket forwarding, and [ADR 0077](0077-content-collections.md)'s bounded portable media transfers.

Every operation retains its declared JSON input and output over socket and WebSocket, and MCP retains the same output as `structuredContent`. An operation may additionally declare a pure `mcpContent` projection of its validated output. The socket owner runs this projection once when the MCP listener explicitly requests MCP presentation; the listener does not load package contexts, guess that arbitrary `base64` fields are images, or execute an operation twice. Without a projection the existing JSON text block remains. This hook belongs to `packages/api`, so any Package API can return MCP text, image, audio, embedded resource, or resource link blocks while retaining typed JSON for other clients.

Content's `item_get` uses the hook: an included document is a text resource, an included image is an image, and an included file is a binary resource; a metadata-only or oversized read offers a link to the configured read-only artifact origin. The same data remains in `structuredContent`, and `item_read` remains a bounded JSON byte-range operation rather than guessing the media type of a chunk. MCP links are not authenticated; they have the same deliberate exposure and reachability limits as Content's static origin. The socket JSON line and WebSocket frame/buffer limits rise to four million characters/bytes so worst-case JSON escaping of bounded 256 KiB content, including the doubled MCP representation, fits. Larger objects still require Content's staged upload and chunked read contracts; the general transports do not become unbounded binary streams.
