# 40. Bind Worker accounts and ACP runtimes to OpenCode V2

Status: accepted, 2026-09-24. Supersedes the V1 executable and credential-format choices in [ADR 0036](0036-account-bound-acp-foundation.md) and [ADR 0039](0039-worker-wakeups-and-scoped-mcp.md), retaining their account ownership and Worker lifecycle boundaries. AgentStart's public-command cutover and V1 executable retirement are separate installation decisions.

Grok and Codex Worker accounts start the fixed AgentStart-installed `~/.local/bin/opencode` V2 executable, guarded by a major-version check. A Worker profile has its own HOME and XDG roots, a V2 config that disables updates and allows only its selected provider, and a private V2 `opencode.db`. The operator uses the returned `auth login --standalone xai|openai` command inside that profile; AgentStack checks a single OAuth credential row and hashes only that credential for duplicate binding detection. Codex still requires its native OpenAI account identity to match the existing Bot account. No ordinary TUI credential or V1 `auth.json` is copied into a live Worker profile; V2's first launch did not automatically import an isolated V1 file.

No-turn V2 ACP probes with separately isolated synthetic credentials verified provider-specific model selectors and their dependent effort options. A bounded real Grok turn loaded a Role skill and completed in a disposable Worker worktree, alongside a native Devin turn. A disposable credential copy was allowed only when the existing V2 OAuth expiration left sufficient time for a no-refresh test, then deleted. Production bindings still require each operator-controlled sign-in and confirmation; the live owner is not restarted by this decision.
