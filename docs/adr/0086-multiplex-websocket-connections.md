# 86. Address Package APIs and subscriptions on one WebSocket connection

Status: accepted, 2026-09-26. Extends [ADR 0010](0010-shared-websocket-transport.md)'s socket forwarding and [ADR 0020](0020-live-websocket-admission.md)'s live admission; supersedes their requirement for a separate connection per Package API.

One `ws://127.0.0.1:<port>/websocket` connection serves all Package APIs declaring the WebSocket Transport. `tools/list` takes `params: {package}`, and `tools/call` takes `params: {package, name, arguments}`. `events/subscribe` takes `params: {package, subscription, topics, scope?}`; the client-chosen subscription ID identifies an independent topic set and scope on that connection. A repeat ID replaces that subscription; `events/unsubscribe` takes `{package, subscription}`. Subscribe acknowledgements and `events/changed` / `events/disconnected` notices include package and subscription so clients can resnapshot only the affected view. Socket Servers still validate topics and scopes; WebSocket operation allowlists still gate direct calls and listing.

Host/Origin checks and current configuration apply at handshake. That connection retains its admitted package set and operation allowlists until it closes; reconnect to discover newly enabled packages. A lost upstream subscription does not disconnect others: the client resubscribes that ID and snapshots its state. The older `/websocket/<package>` paths and unaddressed frames are removed rather than maintained as a second contract. UIX shares one browser WebSocket among package channels and scoped Bot/chat watchers, releasing their subscriptions independently.
