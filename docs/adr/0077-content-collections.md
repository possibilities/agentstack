# 77. Content Package API with optional collections and portable identities

Status: accepted, 2026-09-26. Extends [ADR 0041](0041-isolated-wiki-package-api.md).

Rename the Stack `wiki` Package API and workspace package to `content`. Preserve its plain-file wiki documents, graph, search, Git history, and published static sites without migrating bytes: existing state stays in `<STACK_STATE_DIR>/wiki/vault` and `wiki/artifacts`, with the original `/d/` and `/a/` static URLs. The socket, MCP and WebSocket names become `content`, and `content_status` replaces `wiki_status`. The owner accepts `STACK_CONTENT_PORT` and `STACK_CONTENT_ARTIFACT_PORT`, falling back to the old wiki settings. An authorized owner restart is required for the renamed child; do not restart as part of this change.

Add Content items under `<STACK_STATE_DIR>/wiki/collections`: SQLite holds their metadata and immutable content-addressed objects hold bytes. Every document, file or image can be ungrouped. A named Collection is an optional grouping, not part of item identity. Items have stable IDs, monotonic revisions and revision-fenced updates, moves and deletes. Names are unique within each collection; ungrouped items can share a name because their IDs distinguish them. Deleting a Collection detaches its items rather than deleting them. Opening the earlier collection schema migrates existing records in place without changing IDs or byte references. The canonical item path is `/c/<id>` and stays stable through moves and resurrection on another machine; the original `/c/<collection>/<id>` shape redirects for cited links.

The Package API exposes no local vault or object-store paths. Wiki documents are read and edited by slug/ref and a SHA-256 edit fence, while files and static sites are published from bytes. Base64 transfers are bounded to 256 KiB per call; larger content up to 50 MiB uses resumable, digest-verified blob stages addressed by ID and content hash. Item bytes can be read in bounded chunks via the API without an HTTP URL. Static sites take relative file names within a bundle and staged content digests; their stored URLs remain origin-relative. Existing vault and artifact internals still use files, but agents never need the server's filesystem layout. The earlier path-based `path` and `publish` operations and local-only diagnostic operations are not exposed by this Package API.

The HTTP views remain read-only and use separate origins. The listener defaults to loopback, but the operator may explicitly set `STACK_CONTENT_HOST` and both `STACK_CONTENT_DOCUMENT_ORIGIN` and `STACK_CONTENT_ARTIFACT_ORIGIN` to serve through reachable hostnames or a reverse proxy. The origins must differ; no origin or host is stored in item identity. Exposing either listener makes all served documents and bytes readable to everyone who can reach it: there is no authentication or per-item authorization, so operators must choose network reachability deliberately. Files use attachment disposition, documents use plain-text or Markdown MIME types, and images use a restricted image MIME allowlist. The artifact origin and CSP isolate site scripts from wiki document pages. This change adds no new canvas views, controls or simultaneous editor UI; those require explicit UI scope. Unreferenced old bytes and abandoned blob stages are retained until a separately designed cleanup policy exists.
