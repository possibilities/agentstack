# 52. Bound experimental inference to an explicit Bot account and private socket

Status: accepted, 2026-09-25. Extends [ADR 0001](0001-package-apis.md)'s typed Package API contract and [ADR 0044](0044-owner-usage-observations.md)'s separation of observation from account selection.

The owner starts an `infer` Package API child with `infer_models` and `infer_complete` on the private socket Transport only. Every request names an enabled, non-removing Codex Bot account from `auth`; it never borrows a Worker account or the machine's ambient Codex login. A short-lived, isolated pinned codexnk app-server discovers that account's visible catalog through `model/list` without a thread or turn. Inference checks the selected model and effort against a fresh discovery result, then makes exactly one bounded Responses-shaped HTTPS request to the observed ChatGPT Codex backend. It does not execute tools, create a Bot turn, refresh OAuth tokens, retry ambiguous requests, or fall back to Platform billing. Usage and a local request identifier are returned only on a successful terminal response; an interrupted request reports an unknown outcome.

The backend URL, compatibility headers and credential file layout are observations, **not a supported OpenAI integration contract**. The explicit socket-only surface limits accidental spend through the shared MCP and WebSocket Transports; it is not a sandbox or a quota guarantee. Account owners must assess workspace policy before using this experimental operation and recheck behavior after Codex or service changes. The operator's wiki field guide, “Non-agentic inference with the ChatGPT/Codex model catalog”, supplied the observed route; for supported production integration prefer eligible app-scoped SIWC or the separately billed Platform API. No inference is run by the owner's startup or by discovery.
