# 56. Operate Bots and inspect provider evidence in Fleet

Status: accepted, 2026-09-25. Extends [ADR 0042](0042-canvas-spaces.md), [ADR 0044](0044-owner-usage-observations.md), [ADR 0036](0036-account-bound-acp-foundation.md), and [ADR 0043](0043-bot-chat-apis.md). Supersedes the read-only Bots limitation in [ADR 0024](0024-live-canvas-workbench.md).

Fleet adds Usage and Model catalogs windows alongside its accounts and Bots. Usage is a complete `usage_snapshot` read, refreshed on reconnect and `usage_changed`. Records are keyed by scope plus immutable account ID; machine Grok Bot remains separate. Cards summarize provider measurements; the inspector exposes every nested field and the original JSON. Null stays unknown, stale last-good values keep their observation and attempt times, and a re-read does not claim to force provider collection. These observations never become an account recommendation.

Worker catalogs are account-bound no-turn observations. The shared browser store reads each ready, enabled, non-removing Worker account, coalesces overlapping requests, refreshes after Worker/account invalidations, and fences late results across availability changes. Invalidations during a read schedule a cache-only follow-up so discovery's own notices converge; explicit refresh requests native rediscovery. Source, runtime version, observation time, stale/error state, model IDs, dependent efforts, and separate native Devin IDs remain inspectable. The UI does not substitute a Worker catalog for a Bot runtime's model catalog.

Bots gain explicit creation, start, stop, removal, account assignment, and future-default controls. Start forms preserve omitted saved settings and arguments; they explain that saved arguments can override settings. A running Bot keeps its launched identity after reassignment. Mutation acknowledgements refresh state, including after interruption, without automatically repeating the mutation.

The Bot tools dialog exposes every remaining Bots operation from live discovery, with labelled typed inputs, Bot-bound scope, explicit execution, and complete structured/JSON results. Published defaults remain omittable. This keeps the extensive history, queue, attachment, upload, and speech capabilities usable without inventing a second API contract or an unbounded transcript view. The existing voice controls own WebRTC dial and hangup; speech binds to the selected Bot's exact connected call and rechecks it before submission. Thread actions target only the current main thread; descendant reads remain subject to the API's sanctioned-lineage checks. Durable queue admission is available while stopped. Results are timestamped snapshots with their submitted input; per-Bot invalidation generations survive display-log eviction and advance on notices and subscription interruptions. Native pagination/cursors and queue reconciliation remain explicit inputs and outputs.

A file helper drives the existing upload start/status/chunk/finish operations. It calculates the content digest, uses the acknowledged byte offset, and resumes only after a human action and a new status read. Page-owned per-Bot state retains the selected file, visible upload ID, errors, and receipt across dialog dismissal; it does not persist browser file contents across a page reload. It never sends a chat message implicitly. Read-only API reference windows remain reference surfaces; the operative tools live in Fleet. New node kinds have Fleet homes, deep links, palette entries, and inspector navigation consistent with [ADR 0045](0045-canvas-links-and-inspector-sheet.md).
