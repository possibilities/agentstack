# 47. Unify account management and require an explicit Bot account

Status: accepted, 2026-09-25. Supersedes the active-account selection in [ADR 0004](0004-codex-account-state.md), [ADR 0012](0012-stable-codex-account-ids.md), [ADR 0022](0022-server-account-assignment.md), and the split management surface in [ADR 0036](0036-account-bound-acp-foundation.md). Retains their credential isolation, identity and assignment boundaries.

The `auth` Package API exposes one `account_list` across Codex, Grok and Devin and one `account_set_enabled` and `account_remove` for all three. Every record has `id`, `provider`, `enabled`, `ready`, and `removing`. For Codex, `ready` refers to its optional, separately confirmed ACP Worker sign-in; its Bot device sign-in is established by the existence of the account. Provider-specific sign-in remains separate: Codex device-login operations and native ACP `worker_account_prepare` / `worker_account_confirm`. This avoids pretending that one credential or sign-in flow can serve both native runtimes. `accounts_changed` invalidates the common inventory; the former `worker_account_list`, `worker_account_set_enabled`, `worker_account_remove`, `worker_accounts_changed`, and `account_activate` contracts are removed rather than maintained as parallel aliases. Existing stored credentials and account IDs are preserved; the old selector setting is discarded during migration.

`bot_start` now requires an enabled Codex account ID explicitly, including when returning an existing Bot; for an existing Bot it must equal the saved assignment. Changing that assignment still goes through `bot_assign` and takes effect after a stop/start. The owner restarts saved Bots internally without reselecting an account. Disabled accounts cannot launch a new Bot or Worker process, but disabling does not stop or reassign an already-running Bot. Removal still drains an ACP runtime and deletes bound Bots before deleting Codex credentials. The `usage` Package API remains an observation only: missing, stale, or provider-specific quota values cannot silently change Bot identity, and it is not consulted for launch.
