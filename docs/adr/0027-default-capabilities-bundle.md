# 27. Materialize the default capabilities bundle for each managed Codex launch

Status: accepted, 2026-09-24. Extends [ADR 0005](0005-server-main-threads.md)'s durable thread binding and [ADR 0021](0021-managed-servers-inherit-owner-mcp.md)'s owner MCP inheritance. Replaces ADR 0021's launch `-c` transport for owner MCP connections with a capability `config.toml`.

The public package and bundle names were superseded by [ADR 0030](0030-single-role-package.md); this record preserves the original launch-snapshot rationale.

Every managed Server and Bot shares one default capabilities specification. The `capabilities` Package API stores ordered categories and fragments, human-only descriptions and enabled states in a private SQLite database. All edits carry a global revision precondition and reorder requests are exact permutations, so concurrent editors cannot silently lose an update. The preview renders only enabled instruction bodies, separated by blank lines, with a bounded total size. Deleting a populated category is refused; fragments must first be moved or deleted.

Before each Codex launch AgentStack reads one revision and writes an immutable, private `--capabilities` directory for that Server process. `SYSTEM_APPEND.md` contains the rendered developer instructions; `config.toml` contains the owner's current loopback MCP URLs; `skills/` is reserved for future skill installation. Empty instructions omit the append file. The snapshot remains until the process exits and is removed only after verified process termination. A lost-ownership process keeps its directory. The launched revision is reported separately from the editable revision. A live process never changes merely because the bundle is edited; stopping and starting takes a new snapshot. The Codex TUI may create the Server's first main thread, so per-thread injection by AgentStack would miss that case.

The pinned codexnk runtime explicitly accepts `SYSTEM_APPEND.md` and `[mcp_servers]` in its capabilities directory. Tests inspect its generated private runtime configuration without starting inference. This is a codexnk-specific feature; replacing the runtime requires equivalent support or an explicit migration decision. No prompt content is passed in argv, and caller launch arguments cannot override the managed `developer_instructions` or `mcp_servers` keys. The package advertises socket, MCP, and WebSocket operations and a change Event; the existing canvas discovers it generically but does not yet provide editing controls.
