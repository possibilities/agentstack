# 37. Keep ACP Worker sessions and turns durable in owned worktrees

Status: accepted, 2026-09-24. Extends [ADR 0036](0036-account-bound-acp-foundation.md)'s account-bound ACP processes and [ADR 0032](0032-bot-mcp-invocation-context.md)'s Bot identity. Completion delivery into a Bot thread is a later decision under [ADR 0033](0033-agent-facing-event-subscriptions.md).

The `workers` Package API starts a Worker with an exact enabled account, ACP-advertised model and effort, canonical Git repository, optional base ref and client-generated request UUID. It verifies a Bot caller's current launch and sanctioned main-thread lineage; direct local socket clients act as the operator. A Worker belongs to one Bot, but descendants of that Bot's main thread may inspect and continue it. It claims a fresh branch and worktree from the resolved commit without touching the source checkout's uncommitted files. The worktree contains self-ignored `.devin/` and `.opencode/` skill copies; Devin receives the rendered Role instructions as a user-triggered `/prime` skill that must be called manually. Each Worker snapshots the current Role, including extra MCP definitions, at creation; ACP `session/new` receives those and the owner's local Package API MCP URLs. OpenCode receives rendered Role instruction fragments in the first task message, because the shared per-account ACP process cannot supply a different developer prompt per session. That difference is exposed rather than described as developer-instruction parity. A stricter worker-bound internal MCP identity remains future work; the existing same-user loopback trust boundary applies to these local ACP processes.

The private `workers.sqlite` records Worker and turn phases, idempotency digests, ACP session IDs, selected model/effort and bounded transcript entries. `worker_start` returns after session setup and prompt dispatch, not after inference. `worker_send` adds a new turn only when idle, `worker_read` pages text/tool/plan/stop notices, and `worker_status` reports the current turn and exact pending permission options. Permission requests remain pending until `worker_respond` selects an advertised option or cancels; no automatic approval is inferred. `worker_cancel` acknowledges a cancellation request, not completion. `worker_close` retains the worktree, history, and branch. Explicit `worker_remove` requires `discardWorktree: true` and retains the Git branch.

On process loss or owner restart, in-flight turns become `unknown` and sessions `needs_recovery`; neither a turn nor a permission answer is blindly retried. `worker_resume` uses ACP `session/load` with the original worktree and private Role snapshot. A caller must explicitly acknowledge an unknown turn after inspecting the worktree; loading never reissues its prompt. A later `worker_send` is a new request with its own idempotency key. Account disabling fences admission and stops its ACP process, preserving durable Worker state for inspection. The owner emits payload-free `workers_changed` invalidations; automatic Bot-thread wakeup and delivery reconciliation follow in the collaboration chunk.
