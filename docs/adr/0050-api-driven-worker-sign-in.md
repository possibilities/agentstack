# 50. API-driven Worker sign-in

Status: accepted, 2026-09-25. Amends [ADR 0048](0048-separate-bot-and-worker-sign-ins.md) (and the terminal-command sign-in introduced under ADR 0040), which become the fallback rather than the primary flow.

Worker sign-in now runs inside `auth` like the Codex Bot device sign-in: `worker_account_login_start` spawns the provider's own sign-in CLI in the account's private profile — `opencode auth login --standalone --method chatgpt-headless openai` for Codex, `opencode auth login --standalone --method device xai` for Grok, and `devin auth login --force-manual-token-flow` under a pty for Devin — scrapes only the link and one-time code from its output, and confirms the Worker automatically when the CLI exits. `worker_account_login_status`, `worker_account_login_current`, `worker_account_login_submit`, and `worker_account_login_cancel` expose the attempt, and `worker_login_changed` publishes its transitions. One attempt runs per account; a new start supersedes it, and `worker_account_remove` cancels any pending sign-in before deleting the profile. `worker_account_prepare` and `worker_account_confirm` remain unchanged as the terminal fallback.

Two rules define what the API surfaces. First, links only: the human copies the link into their own browser, and neither the service nor the canvas ever opens one (`BROWSER=/usr/bin/true` on every sign-in child, and the Devin child also gets `SSH_CONNECTION`/`SSH_CLIENT` markers because its browser opener ignores `BROWSER` but skips launching in remote sessions). Second, prompts never cross the API: only anchored URLs and codes are matched and returned — Codex's `auth.openai.com/codex/device`, Grok's `accounts.x.ai/oauth2/device` link (which already carries its `user_code`), and Devin's `app.devin.ai/auth/cli/continue` link. OpenAI's device page did not accept a prefilled `user_code` when checked (2026-09-25), so its link is shown bare. Devin cannot print a code — the site returns it — so its attempt exposes `needsCode`, and `worker_account_login_submit` writes the pasted code to the pty through a `bash <(cat)` bridge: macOS `script` requires a tty-compatible stdin, Node's spawn pipes are sockets, and FIFOs fail the same check. A rejected code re-arms the paste field with an error instead of failing the attempt; Devin's CLI allows one retry and exits after a second rejection, which fails the attempt.
