# 36. Bind worker catalogs to isolated native ACP accounts

Status: accepted, 2026-09-24. Extends [ADR 0012](0012-stable-codex-account-ids.md)'s stable Codex identities, [ADR 0029](0029-bots-own-codex-lifecycle.md)'s Bot boundary, and [ADR 0031](0031-role-resources.md)'s per-launch Role model. Worker turns and Role delivery to workers are subsequent decisions.

The `auth` Package API keeps its existing Codex device sign-in and active selection for Bots. It adds worker account preparation, confirmation, enablement, removal and read-only inventory. Grok and Devin use stable UUIDs and isolated native sign-ins; a Codex worker binding uses its existing Codex UUID and requires a separate OpenCode OAuth login whose native account identity matches the Codex credential. The API does not reuse an OAuth refresh token across Codex and OpenCode writers or import AgentUsage's independent Grok inventory. Native credential files remain in private per-account runtime directories. Operator preparation returns a command to perform the native sign-in in that directory; confirmation checks the selected provider's credential evidence before making it ready. An interrupted removal remains fenced and retryable.

The owner starts a required `workers` Package API child and drains `auth` before it, so an account operation can stop a specific ACP process while its supervisor remains alive. The child starts one stdio ACP v1 process per ready, enabled account, and stops it when disabled or removed. OpenCode and Devin receive account-specific XDG data, config and cache roots; OpenCode's enabled providers are restricted, and Devin's ambient tool-configuration imports are disabled in its private config. Neither ACP pipe nor credentials are exposed through MCP. Existing Bot launch and account selection are unchanged.

`worker_catalog` opens a no-turn ACP session under the account's private probe directory, reads the session's model options, then selects each model to observe its dependent effort options. Devin's `models list --format json` is separately projected as native model IDs, not silently equated with ACP selection IDs. A bounded, coalesced, account-specific cache is fresh for thirty minutes; a failed refresh retains the last good data marked stale. The catalog is evidence for future dispatch validation, not quota, billing or a guarantee that an inference request will succeed. The actual installed OpenCode 1.18.32 and Devin 3000.11.3 ACP handshakes and no-turn selections are verified in the opt-in native probe; account-specific sign-in and entitlement still require distinct live credentials.

This stage deliberately offers no Worker session or turn operations. The next stage will own worktrees, Role materialization and durable ACP turns; the final collaboration stage will bind event subscriptions and Bot lineage to worker ownership before delivering completion notices. The canvas keeps generic Package API discovery and the `/x.md` twin current; new account controls await an explicit UI request.
