# 44. Observe registered accounts without routing them

Status: accepted, 2026-09-25. Extends [ADR 0036](0036-account-bound-acp-foundation.md)'s isolated Worker accounts and [ADR 0012](0012-stable-codex-account-ids.md)'s immutable Codex identities.

Extended by [ADR 0060](0060-claude-sdk-workers.md) for read-only usage of isolated Claude Worker accounts. Amended by [ADR 0066](0066-grok-bot-usage-beside-a-grok-worker.md): Grok Bot is observed only beside a signed-in Grok Worker. Extended by [ADR 0063](0063-usage-subscription-end-and-sample-age.md) with a subscription period end where a provider exposes one.

The owner starts a required `usage` Package API child. It reads the `auth` Package API's Worker account inventory, including Codex accounts without an ACP binding, and observes each ready Grok/Devin account (including disabled accounts) and each non-removing Codex account under its stable Stack ID. It also observes the separately installed, machine-level Grok Bot login. Its only public operation is `usage_snapshot`; the `usage_changed` Event invalidates that snapshot. The operation reports account availability, measurements, last-good time, attempt time, freshness and a bounded error code. No operation chooses an account, changes a credential, claims usage, or tells a caller whether to dispatch a Worker.

The child reads the existing private Codex auth store and native per-account OpenCode/Devin credentials, but never copies credentials into its observation file or exposes them through a Transport. The existing Codex and native runtimes remain the only writers of their respective credentials. The observer uses bounded provider requests and three-minute paced cycles with jitter, longer retry after failure, and a private atomically replaced measurement file under Stack state. A source that has stopped refreshing is marked stale; last-good measurements are not silently presented as current. Provider errors are fixed codes, not upstream bodies or exception text. Account removal prunes its measurement. Grok Bot is explicitly not identified as one of the registered Grok Worker accounts.

Stock OpenCode V2.0.16 exposes `integration.connection.resolve` to plugins, which can trigger its xAI OAuth refresh without a model turn. We do not schedule it for usage: the resolver reads a credential, makes the rotating-token request, then updates the credential without a lock or conditional write. A plugin's timer could overlap a normal model resolution or another location's resolver and attempt to rotate the same token twice. AgentUsage avoids this race for its own separate Grok inventory by owning its credentials and locking the whole refresh and persistence sequence; it does not operate on an OpenCode Worker profile. Neither a separate observer refresh nor that timer is safe under the read-only observer contract. A Worker turn may refresh through the native runtime, or a human can sign in again through Accounts; `usage_snapshot` only reads the last observation.

AgentUsage's `src/observe.ts` and provider observers informed the provider wire shapes, bounds and pacing, but its separately owned account inventory and balancing decisions are not imported into Stack. An expired credential may require the credential owner's native refresh or a new sign-in; usage does not rotate it. The existing canvas discovers the new API generically, while a dedicated usage presentation remains a separate explicit UI request.
