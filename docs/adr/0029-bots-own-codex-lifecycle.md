# 29. Make Bots the sole managed Codex lifecycle

Status: accepted, 2026-09-24. Supersedes the separate Codex Package API and Bot-to-Server composition in [ADR 0001](0001-package-apis.md), [ADR 0007](0007-bot-scoped-change-events.md), and [ADR 0024](0024-live-canvas-workbench.md). Extends [ADR 0028](0028-main-thread-voice-call.md) by moving its operations to Bots. The main-thread, account, recovery, and launch-snapshot guarantees of the intervening decisions remain.

One `bots` Package API owns the supervisor, app-server processes, scoped thread notices, account assignment, and the single voice call. `bot_start` still allocates `bot-N` in its private workspace by default. Optional `id`, `cwd`, and saved `args` expose the earlier `server_start` choices without a second public abstraction. Previously recorded named processes are visible as Bots with their IDs and directories preserved; external working directories are never removed by `bot_remove`. The existing SQLite `servers` and `server_args` tables remain an on-disk compatibility detail, so adoption does not discard credentials, main threads, or history. No `codex` socket, MCP URL, WebSocket route, or package remains.

The owner starts the Bots child with its bound MCP port and drains auth before bots during shutdown. Bots materialize the current default capabilities and owner MCP URLs per launch. `voice_status`, `voice_dial`, and `voice_hangup` now accept/report Bot identity; `voice_changed` is global. Bot event subscriptions accept an optional scope so the canvas can observe global voice state and individual bot invalidations on one transport. The canvas removes its duplicate Servers window and links Bots directly to accounts; index and markdown twins read only `bot_list`.

This is an intentional breaking API change: clients using `server_*`, `codex` transport paths, or a `serverId` voice field must use `bot_*`, `bots`, and `botId`. The process history and bot defaults survive, but there is no compatibility endpoint or inferred alias.
