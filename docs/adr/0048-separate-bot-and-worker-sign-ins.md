# 48. Separate Bot and Worker accounts, correlate only in usage

Status: accepted, 2026-09-25. Supersedes the shared inventory and Codex Worker binding in [ADR 0047](0047-unified-account-inventory-and-explicit-bot-choice.md) and [ADR 0036](0036-account-bound-acp-foundation.md), while retaining [ADR 0040](0040-opencode-v2-worker-accounts.md)'s isolated native OpenCode V2 sign-in. Keep ADR 0047's explicit `bot_start.account` choice and disabled-account launch fence.

`auth.account_list`, `account_set_enabled`, `account_remove`, and the device-login operations manage only Codex **Bot** credentials. `worker_account_list`, `worker_account_prepare`, `worker_account_confirm`, `worker_account_set_enabled`, and `worker_account_remove` manage independently signed-in Codex, Grok, and Devin **Worker** credentials. `accounts_changed` and `worker_accounts_changed` invalidate their respective inventories; both are emitted when either side changes because optional correlation metadata in either inventory may change. A newly prepared Codex Worker receives its own UUID and its own OpenCode V2 OAuth login; no Bot sign-in is required and no identity match against Bot credentials is enforced. Grok and Devin remain Worker-only. Neither a Bot nor a Worker account mutation changes the other's credentials or running processes. Existing Codex Worker rows and private native profiles keep their IDs, even if they historically share a UUID with a Bot account; an ID in one list is never sufficient authority for an operation on the other list.

Both auth inventories and `usage_snapshot` expose automatically derived `linkedAccounts` with only matching AgentStack `(scope, id)` references. Usage identifies each account by `(scope, id)` and reads the appropriate private credential source. The links compare native ChatGPT identities from each private Codex sign-in without persisting or publishing the raw provider identity, access token, or refresh token; absent sign-in or identity evidence yields no link. Correlation is descriptive, not account admission, ownership, reauthentication, or balancing. The prior version-1 usage sidecar is read as Bot Codex and Worker Grok/Devin and rewritten with scoped rows; overlapping legacy IDs remain distinct. The existing Bot auth canvas stays tied to `account_list`. Dedicated Worker sign-in controls are a separate UI request.
