# 101. Serve a scoped remote UIX through Access

Status: accepted, 2026-09-28. Extends [ADR 0091](0091-shared-access-and-direct-tailnet-ingress.md) and [ADR 0096](0096-explicit-transport-exposure.md); qualifies the loopback-only entry in [ADR 0013](0013-owner-managed-ui-canvas.md), adds authenticated remote admission to [ADR 0020](0020-live-websocket-admission.md), and resolves [ADR 0100](0100-content-space.md)'s remote-viewing limitation. The local Next child and local WebSocket remain loopback-only.

## Decision

Access binds a **third, separate TLS origin** on the operator's actual Tailscale address. `AGENTSTACK_ACCESS_UIX_ORIGIN` supplies the exact HTTPS origin (certificate hostname and remote UIX port); the configured DNS name never substitutes for kernel peer and local tailscaled status/self/`whois` evidence. No Serve, Funnel, reverse proxy, public ingress or Tailscale configuration change is authorized. Each HTTP request and WebSocket upgrade repeats provenance verification and refuses forwarding headers. All unsafe UIX-origin HTTP requests and all WebSocket upgrades require the exact `Origin`. The UIX origin is separate from both Content origins by port; document CSP forbids scripts and the Artifact CSP gives scripts an opaque origin without network, forms, frames or top navigation. UIX cookies are host-only, Secure, HttpOnly and SameSite=Strict; they are not readable by either Content origin.

A plain browser creates and saves a 256-bit redemption secret before requesting a browser-kind pairing. Approval, selected scopes, grant updates and revocation remain **trusted-local only**. Redemption uses the existing Access credential rotation; UIX establishment issues a hashed five-minute session and rotating refresh cookie (15-minute browser window, bounded by the existing 30-day credential). Refresh retries use the same deterministic ID for a particular old cookie. Access rechecks client, grant, credential, browser kind, scope and expiry for every HTTP request and WebSocket frame. A grant change or revocation closes existing remote WebSockets immediately; expiry also closes them. Admission and mutating-call receipts enter Access audit. The System Access window shows browser clients, active sessions and audit.

The Access TLS listener forwards authenticated, read-only HTTP page/asset requests to the loopback Next child, stripping caller credentials and forwarding headers and setting a fresh nonce-based CSP and `no-store`. Next recognizes the Access-controlled remote marker and **does not run trusted-local socket snapshot reads** in its remote server render. Its browser connects to the Access-owned instance of the shared WebSocket gateway, not to the local gateway port. That instance resolves current live socket catalogs through the shared exposure resolver, then intersects operations and events with this Access principal's policy. It never imports Package API contexts or exposes the internal MCP listener. `tools/list`, `tools/call` and subscriptions share the same enforced selection.

`uix:view` permits selected `readOnlyHint` operations and events. `uix:control` adds only mutations surfaced by UIX (Bot workbench and lifecycle, Content editing/upload, Role editing, Inbox dismissal, Signal controls and Lab inference). Both require `uix:view` and never widen the package WebSocket selection. `access`, `auth` and `browse` are never available remotely; Bot voice operations and the voice topic are also excluded. This deliberately leaves account sign-in/credential management, calls and headful browser handoff local even for control grants. UIX presents a read-only reason and disables primary editing controls in view mode; the gateway remains authoritative. Remote pages do not receive a trusted-local initial snapshot.

With `content:read`, the UIX's same-origin POST mints a one-use, 60-second Access Content handoff as that session's browser credential for exactly one `/d/<slug>`, `/c/<UUID>`, or immutable `/a/<name>/v/<digest>/` resource. Preview opens `/session#<handoff>` on the correct distinct Content origin in a new tab. The existing 15-minute resource-scoped document cookie or Artifact view path, store checks and sandbox are unchanged. Without `content:read`, the control is disabled with an explanation. A latest Artifact link mints for its resolved immutable version, not its mutable name path.

## Consequences

To enable remote UIX, the operator supplies the existing Access tailnet bind and certificate/key plus an exact UIX origin on a third distinct port before restarting the owner. An existing two-origin Access Brain/Content deployment remains operational without `AGENTSTACK_ACCESS_UIX_ORIGIN`: only the third UIX listener is disabled. Local UIX, local WebSocket, MCP and Next lifecycle remain unchanged. A build in an isolated checkout is needed before an authorized owner restart; neither install check nor this change restarts the running owner. Real tailnet/TLS verification needs an operator-configured listener and a second device. The remote browser is a high-trust reader of the selected Package API data; grant `uix:control` only to a browser that should operate the system.
