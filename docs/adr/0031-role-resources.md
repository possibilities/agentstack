# 31. Keep role skills and extra MCP servers in private launch snapshots

Status: accepted, 2026-09-24. Extends the single Role in [ADR 0030](0030-single-role-package.md) and its inherited launch-snapshot behavior from [ADR 0027](0027-default-capabilities-bundle.md).

The `roles` Package API now stores ordered skills and additional MCP servers alongside instruction fragments in the same revisioned SQLite transaction. Each record has a stable ID, a unique launch name, and an enabled flag; create, update, delete, and exact reorder operations have the same revision precondition as fragments. A skill has a Markdown body and base64-encoded supporting files. AgentStack generates `SKILL.md` metadata, validates relative file paths and bounded payloads, and writes only enabled skills into the Bot's private launch directory. An MCP definition is either HTTP (URL and optional environment-backed token/headers) or stdio (command, args, optional environment). Only enabled definitions join the owner-injected internal MCPs in the launch `config.toml`; collisions with internal Package API names are refused. Edits never change a running Bot.

The Role owns its records and per-launch copies, not ambient Codex configuration. No API mutation writes into a user's home or repository. Codexnk's current `--capabilities` implementation still performs normal project and home skill discovery in addition to these private skills, so AgentStack cannot promise exclusive role skill visibility when those ambient locations contain skills. The human declined an additional carried codexnk patch for now; strict isolation remains a future runtime decision. Internal MCP connections remain isolated by codexnk's existing launch config behavior. A future UI may use the new schemas, but this decision adds no new canvas controls.
