# 54. Observe resources from the owner's process ancestry

Status: accepted, 2026-09-25. Extends [ADR 0001](0001-package-apis.md), [ADR 0023](0023-discovery-snapshot.md), [ADR 0025](0025-app-server-process-ownership.md), [ADR 0029](0029-bots-own-codex-lifecycle.md), and [ADR 0036](0036-account-bound-acp-foundation.md). Resource observations are independent of provider quota/billing [usage observations](0044-owner-usage-observations.md).

The owner Package API owns one single-flight, five-second resource sampler and closes its timer and in-flight work with its context. `owner_resources` reads a cached immutable observation, with paged scopes or process details. `owner_resource_history` reads a bounded in-memory ring of attempts, including explicit failures and absent scopes. `resources_changed` is a payload-free invalidation after an attempt. Requests never launch collectors. `owner_status` retains its shape. The UI gains no controls, cards, subscriptions or resource presentation.

The census starts at the attached owner's process, names its directly owned child components, and follows all observed descendants, including tools and MCP subprocesses. A standalone owner API reports only itself. Exact previously observed PID/birth identities may remain owned after reparenting; ancestry through exited intermediaries is retained while surviving descendants remain observed. Names alone and domain inventories never admit a foreign PID. Bounded Bot and ACP-runtime reads label only descendants already attributed to the corresponding component. Failed domain reads retain labels only on previously observed identities and report their age/source state. Unmatched and recovery-fenced records remain explicit coverage limits. An ACP runtime is shared by an account's Worker sessions; process data cannot honestly allocate costs to a Worker, chat, thread or turn.

macOS uses one bounded `ps` call per attempt; Linux reads `/proc` with bounded concurrency and caches system clock/page constants. Cumulative self user+system CPU deltas use monotonic elapsed time, with 100% equal to one core, null warmup/reset intervals and no fabricated unsupported metrics. Scope membership sets and process self/subtree aggregation avoid counting a PID twice inside a rollup. Different scope kinds overlap intentionally. Sum RSS is not unique physical memory, virtual memory is not committed memory, and host-wide memory/load are separate from AgentStack totals.

Collection timeout/output/process caps, fixed safe errors, response pagination and retention budgets bound cost. A failed collection retains the last good snapshot as stale, inserts a history gap, and cannot create an unhandled timer rejection. Process-capacity exhaustion stops automatic sampling. The ring has at most 120 attempts and 50,000 process records; pressure shortens retention, and restart clears it. The design intentionally adds no persistent database, native helper or dependency.

This is sampled observation, not complete OS accounting: short-lived processes, descendants detached before first observation, inaccessible processes and remote services may be missed. macOS `ps` birth identity has one-second resolution and cannot distinguish pathological same-PID reuse within that second; Linux uses boot ID plus start ticks. Enumeration and domain lookup are not an atomic kernel snapshot. See [the consumer contract](../owner-resources.md) for units, selection, charting and these limits.
