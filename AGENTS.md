# Stack repository guidance

- Commit completed changes as you go and land them on `main`.
- Keep working files, handoffs, scratch notes, and temporary Markdown in `~/scratch`, outside the repository. Do not put them in project docs or commit them. Reserve project documentation for durable, maintained material such as architecture decisions, contracts, and runbooks.
- Use the terms in [`CONTEXT.md`](CONTEXT.md) and the decisions in [`docs/adr/`](docs/adr/) when changing a Package API or Server lifecycle.
- A Package API declares its transports in `packages/<name>/api.yaml` and its typed operations and events in `packages/<name>/api.ts`. Shared socket, MCP, WebSocket, and discovery code lives in `packages/api/`; the process server lives in `packages/serve/`.
- MCP and WebSocket declarations require independent `operations` and `events` selections (`all`, positive names, or `[]`). Keep exposure in the manifest and behavior in operation descriptions. Use the shared exposure resolver. Internal stdio discovery uses installed typed declarations without package contexts; external HTTP and WebSocket gateways validate live socket metadata. Standalone execution requires explicit owner opt-in and definite pre-dispatch socket absence; never infer it from a read-only hint or replay an ambiguous call. See [ADR 0096](docs/adr/0096-explicit-transport-exposure.md) and [ADR 0146](docs/adr/0146-server-independent-internal-mcp.md).
- Managed runtime settings use the shared `packages/settings` contract through Bots and Workers. Preserve omission, false, empty strings and native null; saving is separate from application and observed effective state. New controls stay unset unless explicitly selected. See [ADR 0128](docs/adr/0128-managed-runtime-settings.md).
- Keep operation schemas, descriptions, and package exports in sync. The live reference uses `docs_snapshot`; update its tests when the discovery contract changes.
- Codex `turn/start` is native start-or-steer admission. Subscription snapshots use standalone `toolOutput`; chat uses typed input. Return on admission, never poll for idle or wait for turn completion. Chat `threadState` is a pre-send observation, not an atomic admission result. See [ADR 0120](docs/adr/0120-codex-native-input-admission.md).
- `pnpm test` builds the packages and runs their compiled tests. Use a disposable `STACK_STATE_DIR` for lifecycle checks; never claim or remove a live server's socket to make a test pass.
- `scripts/install.sh --check` prints the installation plan. `--install` installs the pinned codexnk runtime, builds, and links the command; neither command restarts a running server.
- A Bot's `mainThreadId` is its sanctioned root. Stack thread and future subagent views must include only that root and its descendants. Other top-level Codex threads on the same socket are not Bot threads; `threads_changed` is an invalidation notice, not evidence that a sanctioned thread changed.
- `packages/hud` owns semantic Work, metadata, collaboration history and Chat focus. Worker admissions capture Work context in the Worker ledger; native completion never completes Work. Resource views refresh from HUD and Worker events independently. See [ADR 0132](docs/adr/0132-native-hud-work-collaboration.md).

## Brain and device clients

- `packages/client` owns the independent same-user Client host, cold installation, local user-service/login control and destination-pinned connections. It is not a platform Package API or remote installer. Keep native credentials out of WebViews; Access UI handoffs mint independent scoped viewer sessions. See [ADR 0152](docs/adr/0152-independent-client-bootstrap-and-ui-handoffs.md) and [the client contract](docs/client-bootstrap.md). Standalone UI and `packages/desk` remain separate phases.

- `packages/brain` owns research admission, the ingestion ledger and index writes. URL extraction and source discovery use the Stack-owned `packages/scrape` engine; Scrape owns preset validation, egress policy and browser page extraction. Admission is not indexing completion; an Ingestion worker is not an ACP Worker.
- Brain defaults belong under `<STACK_STATE_DIR>/brain`. Never import an existing research store, source manifest, token or client settings as part of setup or a test. The Chrome and Android packages are Stack applications, with sharing as their first feature.
- Preserve the maintenance invariants in [`docs/brain-maintenance.md`](docs/brain-maintenance.md) and the device [share contract](docs/brain-share-contract.md), including read-only retrieval, fenced completion, full FTS row replacement, and destination-bound Share outboxes.

Its data layer is in `lib/stack/` (spaces and each node's destination in `lib/stack/spaces.ts`) and its components are in `components/canvas/` (each space's `WindowDef` registrations in `spaces.tsx`). Links reveal a card or global dock entry (`goTo`); a card's name explicitly inspects it ([ADR 0051](docs/adr/0051-explicit-inspect-controls.md)). Space navigation switches visible benches, restores independent cameras and retains inspection and window state. Hidden benches are not visible or interactive; shared providers and global tools remain mounted. Keep window registrations and card bodies independent of bench geometry so other window work can integrate cleanly.

Fleet also has chat windows following each Bot's main thread ([ADR 0080](docs/adr/0080-fleet-chat-windows.md)).
Existing owner views also expose Signal checkpoint rebaseline, retained Role launch-directory clearing, exact-target old settings receipts, Codex/OpenCode model-cache clearing in the Worker-account inspector and expired Access history by kind, all through the local shared plan/receipt flow ([ADR 0139](docs/adr/0139-owner-maintenance-in-existing-spaces.md)). These never implicitly drain, resume, launch or apply settings; Access audit retention is automatic only.
Workers also expose closed-Worker worktree reset, transcript redaction, exact native-session purge and recorded branch collection, plus account-shared derived catalog clearing. Retained branch claims outlive Worker records; unmerged collection requires deliberate per-branch consent. Unknown/partial Worker maintenance receipts remain read-only recovery, never a rerun. Lifecycle and permission controls stay separate.
Browse exposes exact profile reset and cookies/storage/CacheStorage clearing in profile dialogs, fenced receipt inspection and scoped release, resolved-handoff content redaction in History, and paged owned-volume collection under Toolchain Hypeman. Reset, site data and volumes use receipt-only recovery for partial/unknown effects; fence release only acknowledges inspection. No implicit Bot stop, controller closure, browser start/navigation or VM launch; scoped HTTP-cache/history clearing is unsupported.
Lab inference uses the durable request ledger and asynchronous admission ([ADR 0081](docs/adr/0081-infer-request-ledger-api.md)).
The Roles Preview's Launch view reads `role_launch_preview` for everything a launch receives besides instructions.
Artifact publishing and Content's `gc`, `commit`, `doctor`, `reindex`, `path` and `publish` remain API-only.

- **Always maintain it.** When you change a Package API's operations, output fields, events, scopes, or transports, update the UI in the same change so it still compiles and still shows the truth: `lib/stack/types.ts`, the store's reads and subscriptions, and the affected cards and inspector views. Renamed, removed, or re-typed data must never silently break or go stale in the UI. Run `pnpm --filter @stack/ui typecheck`.
- **Never extend it implicitly.** Do not add new spaces, windows, cards, views, controls, mutating actions, interaction patterns, or UI dependencies as a side effect of other work. When new UI is requested, put it in its appropriate space and give any new node kind a destination in `lib/stack/spaces.ts` so links and focus reach it. New UI is added only when the human explicitly asks for it. The inspector already renders every record field generically, so new fields on existing records need no new UI.
- **Nag the human instead.** If your change adds something the UI does not yet express (a new Package API, operation, event, record state, or a workflow that would benefit from a control), do not build it. Tell the human in your final report: say what is missing and suggest the UI it might need, then ask whether to build it. Repeat the reminder at later boundaries while it stays unresolved.
- Changes reach the server-served app only after a rebuild and an authorized server restart ([ADR 0013](docs/adr/0013-owner-managed-ui-canvas.md)). A rebuild replaces the `.next` directory a running server is serving, so do not rebuild in place under a live server without the human's go-ahead. Use `next dev` or a separate checkout for verification: `pnpm --filter @stack/ui dev` from the workspace root. Add UI primitives from `packages/ui` with `pnpm dlx shadcn@latest add <component>`. The UI app serves no markdown twins.
- Remote UI is an Access-authenticated browser session on its own direct-tailnet TLS origin ([ADR 0101](docs/adr/0101-remote-uix-through-access.md)); it is not a forwarded local WebSocket. Keep remote server renders free of trusted-local socket snapshots, intersect operation/topic selection with live WebSocket exposure, fence open connections on Access changes, and keep Content handoffs resource-scoped. Local Access approval and credential controls, `auth`, `proc`, Role shims, voice and headful browser handoff remain unavailable remotely.
