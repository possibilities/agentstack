# AgentStack repository guidance

- Commit completed changes as you go and land them on `main`.
- Use the terms in [`CONTEXT.md`](CONTEXT.md) and the decisions in [`docs/adr/`](docs/adr/) when changing a Package API or Server lifecycle.
- A Package API declares its transports in `packages/<name>/api.yaml` and its typed operations and events in `packages/<name>/api.ts`. Shared socket, MCP, WebSocket, and discovery code lives in `packages/api/`; the process server lives in `packages/serve/`.
- MCP and WebSocket declarations require independent `operations` and `events` selections (`all`, positive names, or `[]`). Keep availability in the manifest and behavior in operation descriptions. Use the shared exposure resolver; gateways validate live socket metadata without creating package contexts. See [ADR 0096](docs/adr/0096-explicit-transport-exposure.md).
- Keep operation schemas, descriptions, and package exports in sync. The live reference uses `docs_snapshot`; update its tests when the discovery contract changes.
- `pnpm test` builds the packages and runs their compiled tests. Use a disposable `AGENTSTACK_STATE_DIR` for lifecycle checks; never claim or remove a live server's socket to make a test pass.
- `scripts/install.sh --check` prints the installation plan. `--install` installs the pinned codexnk runtime, builds, and links the command; neither command restarts a running server.
- A Bot's `mainThreadId` is its sanctioned root. AgentStack thread and future subagent views must include only that root and its descendants. Other top-level Codex threads on the same socket are not Bot threads; `threads_changed` is an invalidation notice, not evidence that a sanctioned thread changed.

## Brain and device clients

- `packages/brain` owns research admission, the ingestion ledger and index writes. URL extraction and source discovery use the AgentStack-owned `packages/scrape` engine; Scrape owns preset validation, egress policy and browser page extraction. Admission is not indexing completion; an Ingestion worker is not an ACP Worker.
- Brain defaults belong under `<AGENTSTACK_STATE_DIR>/brain`. Never import an existing research store, source manifest, token or client settings as part of setup or a test. The Chrome and Android packages are AgentStack applications, with sharing as their first feature.
- Preserve the maintenance invariants in [`docs/brain-maintenance.md`](docs/brain-maintenance.md) and the device [share contract](docs/brain-share-contract.md), including read-only retrieval, fenced completion, full FTS row replacement, and destination-bound Share outboxes.

## The UI (`packages/ui`)

`packages/ui` is the central UI for interacting with AgentStack; `/` serves Fleet ([ADR 0116](docs/adr/0116-ui-at-root.md)). Each Canvas space has its own open bench addressed by `/<space>` ([ADR 0088](docs/adr/0088-isolated-space-benches.md)): Fleet (Bots), Accounts (accounts, usage and model catalogs; [ADR 0069](docs/adr/0069-accounts-space.md)), Lab (experiment windows such as Call speech and Inference; [ADR 0073](docs/adr/0073-lab-space-and-call-speech.md), [ADR 0074](docs/adr/0074-lab-inference-over-websocket.md)), System (server status and runtime, package channels, host resources, observed processes and sampling; [ADR 0079](docs/adr/0079-system-space.md)), Roles (instruction Categories and Fragments, skills, MCP servers and trusted projects; [ADR 0082](docs/adr/0082-roles-space-for-instruction-fragments.md), [ADR 0098](docs/adr/0098-roles-space-for-launch-resources.md)), Inbox (Notifications to read, answer and dismiss; [ADR 0097](docs/adr/0097-inbox-space-for-notifications.md)), Signal (conversation attention, captured messages, interpretation runs and traces; [ADR 0099](docs/adr/0099-signal-space.md)) Content (Vault documents, collections, items and Artifacts; [ADR 0100](docs/adr/0100-content-space.md)), Workers (read-only Worker conversations, changes, turns, tools, records and runtimes; [ADR 0102](docs/adr/0102-workers-space.md), [ADR 0104](docs/adr/0104-worker-diff-and-list-summaries.md)), Scrape (extraction, feeds, presets, checks and the scrape-to-file queue; [ADR 0103](docs/adr/0103-scrape-space-and-local-operator-exposure.md)), Browse (Browser handoffs, profile viewers, profiles, controllers and the browser toolchain; [ADR 0108](docs/adr/0108-browse-space.md)) and Brain (research search and reading, admission, the ingestion ledger and recurring sources; [ADR 0109](docs/adr/0109-brain-space.md)), plus Proc (schedules, executions, process runs and their output; [ADR 0111](docs/adr/0111-proc-space.md)), joined by card links rather than wires. API reference shares the right dock with record inspection; the inspector dock can be pinned and otherwise contracts on outside bench input ([ADR 0085](docs/adr/0085-pinnable-inspector.md)). It operates `auth` ([canvas auth controls](docs/adr/0026-canvas-auth-controls.md) and [Worker accounts](docs/adr/0049-canvas-worker-account-controls.md)), Bots and their full operation workbench, usage observations and Worker model catalogs ([ADR 0056](docs/adr/0056-fleet-usage-catalogs-and-bot-controls.md)), Codex voice calls ([ADR 0028](docs/adr/0028-main-thread-voice-call.md)), `infer` requests in the Lab, the whole Role, `notify` dismissals, Signal's processing switch, defaults, feedback and replay, Content documents, collections, items and Artifact tombstones, Scrape extraction, canary checks and scrape-to-file jobs, Browser handoff take/finish, profile creation and deletion and the browser toolchain, and Brain admission, job dispositions, audited reveal, source sync and pause, and document deletion, Proc run stop, schedule disable/enable/removal and legacy reauthorization; other APIs remain read-only there. Its data layer is in `lib/stack/` (spaces and each node's destination in `lib/stack/spaces.ts`) and its components are in `components/canvas/` (each space's `WindowDef` registrations in `spaces.tsx`). Links reveal a card or global dock entry (`goTo`); a card's name explicitly inspects it ([ADR 0051](docs/adr/0051-explicit-inspect-controls.md)). Space navigation switches visible benches, restores independent cameras and retains inspection and window state. Hidden benches are not visible or interactive; shared providers and global tools remain mounted. Keep window registrations and card bodies independent of bench geometry so other window work can integrate cleanly.

Fleet also has chat windows following each Bot's main thread ([ADR 0080](docs/adr/0080-fleet-chat-windows.md)).
Lab inference uses the durable request ledger and asynchronous admission ([ADR 0081](docs/adr/0081-infer-request-ledger-api.md)).
The Roles Preview's Launch view reads `role_launch_preview` for everything a launch receives besides instructions.
Artifact publishing and Content's `gc`, `commit`, `doctor`, `reindex`, `path` and `publish` remain API-only.

- **Always maintain it.** When you change a Package API's operations, output fields, events, scopes, or transports, update the UI in the same change so it still compiles and still shows the truth: `lib/stack/types.ts`, the store's reads and subscriptions, and the affected cards and inspector views. Renamed, removed, or re-typed data must never silently break or go stale in the UI. Run `pnpm --filter @agentstack/ui typecheck`.
- **Never extend it implicitly.** Do not add new spaces, windows, cards, views, controls, mutating actions, interaction patterns, or UI dependencies as a side effect of other work. When new UI is requested, put it in its appropriate space and give any new node kind a destination in `lib/stack/spaces.ts` so links and focus reach it. New UI is added only when the human explicitly asks for it. The inspector already renders every record field generically, so new fields on existing records need no new UI.
- **Nag the human instead.** If your change adds something the UI does not yet express (a new Package API, operation, event, record state, or a workflow that would benefit from a control), do not build it. Tell the human in your final report: say what is missing and suggest the UI it might need, then ask whether to build it. Repeat the reminder at later boundaries while it stays unresolved.
- Changes reach the server-served app only after a rebuild and an authorized server restart ([ADR 0013](docs/adr/0013-owner-managed-ui-canvas.md)). A rebuild replaces the `.next` directory a running server is serving, so do not rebuild in place under a live server without the human's go-ahead. Use `next dev` or a separate checkout for verification: `pnpm --filter @agentstack/ui dev` from the workspace root. Add UI primitives from `packages/ui` with `pnpm dlx shadcn@latest add <component>`. The UI app serves no markdown twins.
- Remote UI is an Access-authenticated browser session on its own direct-tailnet TLS origin ([ADR 0101](docs/adr/0101-remote-uix-through-access.md)); it is not a forwarded local WebSocket. Keep remote server renders free of trusted-local socket snapshots, intersect operation/topic selection with live WebSocket exposure, fence open connections on Access changes, and keep Content handoffs resource-scoped. Local Access approval and credential controls, `auth`, `proc`, voice and headful browser handoff remain unavailable remotely.
